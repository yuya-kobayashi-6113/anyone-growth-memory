# Growth 帳票出力(2026-08-20 マージ済み)

> 提案書(正本)は `session-docs/growth-plan-18-document-output.md`(第4版・承認済み)。
> **PR番号やテスト件数はここに書き写さない。**数え方は [[github-repos]] の表を見る。

## 位置づけ
- Growth(フェーズ2)の見積機能の上に載る最初の帳票機能。**見積書のExcel出力**まで。
- **PDFは第2弾**。Aspose.Cellsが単体で変換できるので追加ライブラリは要らない。**必要なのは日本語フォントをコンテナに入れる作業と、その回帰を止めるテスト**。

## 決めたこと【提案書の判断1〜14 = すべて承認済み】

1. **`services/Growth.Documents` をクラスライブラリとして新設し、Growth.Api が参照する。**別プロセスにはしない。帳票生成が重くなったとき(PDF同梱時が最有力)に切り出せるよう境界だけ先に切った
2. **プレースホルダの記法は `{{見積.物件名}}`**(二重波かっこ)。`$$...$$` は**Excelの絶対参照 `$A$1` と紛らわしい**のと、**開始と終了が同じ記号で閉じ忘れを検出できない**ため見送った。帳票テンプレートの世間の主流も `{{ }}`(ClosedXML.Report / Handlebars / Jinja2 / Liquid)
3. **Smart Marker は使わず自前の行展開エンジンにした**(実装で判明)。分類→明細→小計の**入れ子順の出力**と、**セル文字列の一部にプレースホルダを混ぜる書き方**(`{{見積.顧客名}} 御中`)が Smart Marker では表現できない
4. **出力設定は「項目定義の一覧をサーバーが返し、画面がフォームを組み立てる」**。設定が増えても**エンドポイント0本・画面0枚**。部品は オン/オフ・数値・選択肢・自由入力・日付・テンプレート選択 の6種。**部品の種類を増やすときだけフロントを直す**
5. **カスタムテンプレートは会社×帳票種別ごとに複数持て、1つを既定にできる。**選択順は 指定 → 会社の既定カスタム → 共通
6. **対応形式は `.xlsx` / `.xlsm` / `.xls`。**出力形式はテンプレートと同じにする
7. **生成物は保存する**(証跡)。`expires_at` 列だけ先に入れ、定期削除は第2弾
8. **APIの形は非同期前提、実装は同期完了。**将来のAI生成資料を同じ窓口に載せられるようにするため

## 税区分は見積の版が持つ(2026-08-23 マージ済み)

**税区分(外税/内税)を帳票の出力設定から見積の版の属性へ移した。**決定と却下した案の正は、リポジトリの `docs/adr/0002-estimate-tax-mode-attribute.md`。

- 移す前は出力するたびに選ぶ形で、**同じ見積でも出力する人によって金額が変わり得た**。当初は見積側に列が無く、帳票そのものを先に出せるようにするための暫定だった(ADR-0001 の決定9の末尾)
- **版ごとにしたのは、消費税率がすでに版ごとだから。**片方だけ粒度が違うと、版を切り替えたときに税率は変わるのに税区分は変わらないというねじれが出る。「見積の属性」という当初の表現は「出力のたびに選ぶものではない」という趣旨で、版との粒度差までは決めていなかった

**つまずいた型: 「共通だから共通ライブラリ」で置き場所を決めない。**外税・内税を表す値の定数を帳票の共通ライブラリに残したまま出力設定から消したところ、**共通ライブラリ側では誰も使わなくなり、見積ドメインが帳票ライブラリを参照する逆向きの依存だけが残った。**置き場所は使用実態を見てから決める。移設後、見積側から帳票ライブラリへの参照はゼロになった。

**ADRは既存を書き換えず新しく建てる。**このとき ADR-0001 の記述を直そうとして誤りかけた。運用ルールはリポジトリの `docs/adr/README.md` が正。

## 画面と帳票で合計の集計基準が違う【未解決・別タスクで調査中】

**見積表紙の「出力時の御見積合計」と、帳票に出る金額は、違う基準で集計している。**

- 画面は**計算対象**(`includeInCalc`)、帳票は**出力対象**(`includeInOutput`)で小計を作っている
- 2026-08-23 の税区分の作業で**税額の計算式と端数処理は帳票へ揃えた**が、**その元になる小計の母数が違う問題は残っている**。両フラグが食い違う見積では、画面で確認した合計と発行される見積書の合計がずれる
- ラベルが「出力時の」と書いているのに出力時の基準で計算していない点も食い違い
- **粗利・原価にも同じ問題があるかは未確認。**どちらを正とするかは画面上部の集計表示の意味にも波及するため、実装前に判断が要る

## Aspose.Cells の罠【実際に踏んだもの】

- **Linux では SkiaSharp のネイティブ実体が必須。**無いと `new Workbook()` を1つ作っただけで**GCのタイミングでプロセスごと落ちる**(例外にならない)。`SkiaSharp.NativeAssets.Linux.NoDependencies` を入れ、**版はAsposeが推移的に参照するSkiaSharp本体と同じに揃える**(版がずれると別の事故になる)
- **ライセンス未適用でも例外を投げず、評価版として動く。**出力に「Evaluation Warning」シートが1枚増える。**気づかないまま顧客に透かし入りの見積書を出す事故になる**ので、起動時に `Workbook.IsLicensed` を見て**適用に失敗したら起動を止める**。生成の直前にも確認する
- **ライセンスは `SetLicense(Stream)` で渡せる。**環境変数のBase64 → MemoryStream で後付けできる。リポジトリにコミットしない
- **`CalculateFormula()` は循環参照でも例外を投げず 0 を返す。**循環参照の検出は計算モニタでしか取れない
- **`=SUM(F10:F10)` のような単一行範囲は、行挿入では伸びない。**さらに分類行・小計行を挟むと明細行が飛び飛びになる。**Excelの共用体参照**(`=SUM((G12:G14,G17:G19))`)を生成する方式で解決した
- **`.xls` は Aspose 側が 65,536行を強制する**ため「展開してから超過を検出」ができない。**展開前に必要行数を計算して止める**
- **生成の最後に必ず再計算する。**しないと値が入っていないファイルになり、第2弾のPDF化では空またはゼロのPDFになる

## テンプレートの作り【要点】

- シートは `template`(様式の本体)と `sample`(差し込み項目の一覧表。**システムが自動生成**し、ダウンロード時に添付する)。**`sample` はシステムが読まない**ので、顧客が消しても壊れない
- 繰り返し行マーカーは `{{#明細}}` / `{{#分類}}` / `{{#小計}}`。書式・行高・結合・罫線ごと複製する
- 行ごとの数式は `{{式: D{行} * F{行} }}`。**`=D{行}*F{行}` と直接書くとExcelが数式として受け付けない**(`{` が配列定数の記号のため)。プレースホルダの中に入れると文字列として入るので通る
- **アップロード時の検査は29項目**。エラー(保存しない)と警告(保存して出し続ける)を分ける。要点は**サンプルデータで実際に1回生成し、再計算して数式のエラー値が無いことまで確認する**こと
- **`会社.名称` は提供しない。**発行元の会社名はID基盤側にあり、Growthは会社IDしか持たない(**context token にも入っていない**)。置くと必ず空欄になる

## 既存コードで踏んだこと

- **重要操作トークンは4箇所セットで登録しないと発行も検証もできない**(種別の定数 / 既知種別の判定 / 期待値の生成 / 発行前の確認)。フロントの `/api/critical-actions` にも許可リストがある。**計5か所**
- **リクエストボディの4MB上限は `Program.cs` の自前設定**(フレームワーク既定ではない)。10MBのテンプレートは最初から通らなかった。エンドポイント単位で上げる
- **マイグレーションの ModelSnapshot は EF の生成形式ではなく手書きのミラー形式。**`dotnet ef migrations add` をそのまま使うと形式が壊れる
- **ASP.NET Core の TestServer は本文サイズ上限の機能を持たない**ため、エンドポイント単位の上限は結合テストで実効しない
- **BFF の中継は JSON 固定だった。**バイナリを流すには `growthApiFetchResponse` の拡張と、`content-disposition` を BFF 側で組み直す実装が要る(転送してよいヘッダーは4つだけ)
- **右から出るドロワーの共通部品は無かった。**`app-modal.tsx` とフォーカス制御を共通化して新設した

## 残っている制約・やり残し

- **共通テンプレートを base64 テキストで同梱している。**クラウドの実装環境から GitHub へバイナリを push できないため(→[[env-pitfalls]])。**手元で `.xlsx` を直接コミットすれば外せる。**戻し方はコード内のコメントとPR本文にある
- **ライセンスは未入手のまま実装した。**評価版で全テストが緑になることは確認済み。**透かしが消えることだけ未検証**
- **PDF出力の実測(2026-08-25)**: `SaveFormat.Pdf` で変換でき、日本語も正常に出る。**評価版の透かしはExcelと出方が違い、シートが増えるのではなくPDF1ページ目の先頭に赤字1行が入る**(`Evaluation Only. Created with Aspose.Cells for .NET...`)。**ただし本番はライセンス必須で未設定なら起動が止まる設計のため、透かし入りが客先へ出る経路は無い**。PDF実装をライセンス待ちで保留する必要はない(2026-08-25 に取りまとめ担当が誤って保留を提案し、小林さんの指摘で訂正)
- **ライセンスの効き方は環境で分かれる**(2026-08-20 実機確認)。`launchSettings.json` が `ASPNETCORE_ENVIRONMENT=Development` に固定し、`appsettings.Development.json` に `AllowEvaluation: true` があるため、**ローカルとCIはライセンス無しでも警告1行を出して起動する**。**本番だけ起動を止める**。さらに**本番で `AllowEvaluation: true` を設定すると起動時検証が弾く**ので、逃げ道も塞いである。**CIへのSecrets登録は不要**
- **生成の冪等性が無い。**同じ `idempotencyKey` で2回叩くと生成物が2件できる
- テンプレートの上限値(10MB)が検査・BFF・エンドポイントの3か所に分散している
- `.xlsm` の「生成後にマクロが残ること」の回帰テストが無い
- **実ブラウザでの通し確認が未実施**
