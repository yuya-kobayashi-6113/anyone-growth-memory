# 体制と前提

- **開発**: allsmile社 / **納品先**: エニワン社(共通ID基盤・Growthの運営主体は同一法人エニワン)
- **意思決定者**: 小林祐也さん(y.kobayashi@allsmile.co.jp)。共通ID基盤・Growthの両方の承認者
- **役割**: PMがメイン。技術者経験は3年程度あり基礎は分かるが、深い技術詳細の解像度は高くない(本人申告 2026-08-04)
- **閲覧環境**: スマホからも設計HTMLを見る。このため**HTML内の図は外部ライブラリに依存させずSVGを直接埋め込む**(スマホでmermaidが描画されなかった実害がある)
- **環境**: 弊社テスト(GitHub Actions)/ エニワンテスト(Azure DevOps)/ 本番 の3系統。全部別サーバー

## 案件固有の説明ルール
- 承認を求める要約は非技術者向けに翻訳し、判断ポイントをトレードオフとして提示する。詳細設計文書の冒頭に「PM向けサマリ」を置く
- 技術ドキュメント本体は開発メンバー向けの正確さを維持する
- 顧客(エニワン社)に聞かれたときの即答メモは→[[tech-stack]](PostgreSQL・Keycloakの選定理由)

> 進め方・成果物のスタイル・報告の型・迎合禁止といった共通ルールは **allsmile-ops スキル**(deliverable-style / dev-workflow / no-sycophancy / memory-ops)が正。ここには案件固有の前提だけを置く。
